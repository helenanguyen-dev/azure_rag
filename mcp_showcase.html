An Azure docs assistant that always shows its work

This assistant doesn't store or search its own copy of Microsoft's documentation. Instead, every answer is retrieved live through the Microsoft Learn MCP server — the same protocol Anthropic introduced to let AI models call external tools directly, safely, and transparently.

How it works

From question to grounded answer

MCP (Model Context Protocol) is an open standard for connecting an AI model to external tools and data sources — instead of the model guessing from memory, it can call a real tool and use what comes back.
1

You ask a question

e.g. "What's the default idle timeout for App Service?"

2

Agent calls a tool

The model decides to invoke microsoft_docs_search rather than answer from memory

3

MCP server queries Learn

Microsoft's own MCP server searches live documentation and returns real excerpts + URLs

4

Grounded answer returned

The model answers using only what the tool returned, citing the source

Available tools

What this assistant can call

The Microsoft Learn MCP server (learn.microsoft.com/api/mcp) exposes three tools over Streamable HTTP, no authentication required.
microsoft_docs_search

Searches official Microsoft documentation and returns relevant excerpts with source URLs.

microsoft_docs_fetch

Retrieves the full content of a specific documentation page when a snippet isn't enough.

microsoft_code_sample_search

Finds official code samples relevant to a given Azure service or API.

Design decision

Why move from a custom RAG pipeline to MCP

The earlier version of this project used a self-built retrieval pipeline — a curated document corpus, custom chunking, and a vector store. It worked, but came with real tradeoffs.
Before — custom RAG

Self-hosted vector store

  • Required manually curating and chunking ~127 documents
  • Chunking strategy directly affected answer quality
  • Citations required custom metadata engineering
  • Knowledge base goes stale unless re-ingested
Now — MCP

Tool-orchestrated retrieval

  • No document ingestion or chunking to maintain
  • Always queries Microsoft's current, live documentation
  • Source URLs returned directly by the tool
  • Simpler to reason about — a build-vs-buy tradeoff, not a strictly "better" system
